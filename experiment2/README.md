## 一、实验目的

1. 掌握用 Streamlit 快速搭建交互式数据看板的方法。
2. 理解 `st.session_state` 在页面多次刷新之间保持数据的作用。
3. 掌握用 pandas 做多维分组聚合，用 Plotly 绘制柱状图、饼图、折线图、热力图、雷达图与仪表盘。
4. 学会用阈值规则实现业务预警，并把当前筛选结果导出为 CSV。

## 三、数据说明

[`generate_data.py`](./generate_data.py) 用固定随机种子 42 生成模拟数据，写出 [`city_traffic.csv`](./city_traffic.csv)（UTF-8-SIG，840 行数据 + 1 行表头）：

- 维度：7 天（2024-06-01 至 06-07）× 24 小时 × 5 个区域（城东、城西、城南、城北、市中心）。
- 字段：日期、小时、区域、路段、交通方式、车流量、平均车速、拥堵指数、事故数。
- 生成逻辑：早晚高峰（7-9 点、17-19 点）基准车流量 800，白天（10-16 点）500，夜间 150；车流量取正态分布并设下限 20；平均车速约为 45 减去车流量的百分之一；拥堵指数为车流量除以 1000 再乘 10，上限 10；事故数按泊松分布抽样，拥堵越重期望值越高。

[`app.py`](./app.py) 内置同一套生成逻辑，但把结果放进 `st.session_state` 而不是直接读 CSV，这样每次交互刷新不会重新生成数据；CSV 作为原始数据样本与结果证据保留在目录中。

## 四、功能设计

| 模块 | 实现 | 位置 |
| --- | --- | --- |
| 亮暗主题 | 侧边栏 `st.radio` 切换，注入 CSS 改变背景、文字与指标卡配色，并加入淡入动画 | `app.py` 主题样式注入段 |
| 侧边栏筛选 | 日期、区域、交通方式三个 `st.multiselect`，默认全选；筛选后为空时提示并停止渲染 | 侧边栏筛选条件段 |
| 实时刷新 | 自动刷新开关 + 3 至 60 秒间隔滑块；另有「手动新增一批数据」按钮，追加当前时刻各区域记录后重跑 | 侧边栏实时刷新段 |
| 阈值预警 | 平均拥堵指数超过 7.0 时闪烁红色告警，事故总数超过 5 时黄色提示，否则显示绿色正常 | 预警监控段 |
| 核心指标 | 总车流量、平均车速、平均拥堵指数（带相对阈值的 delta）、事故总数四个指标卡 | 数据概览区 |
| 维度图表 | 各区域车流量柱状图、交通方式占比饼图、24 小时车流量趋势折线图、路段拥堵排名横向条形图 | 维度统计与趋势分析区 |
| 多维分析 | 区域-小时车流量热力图、各区域综合指标雷达图（先做极差归一化）、平均拥堵指数仪表盘 | 多维度分析区 |
| 区域钻取 | 下拉选择区域，显示该区域记录数、总车流量与前 50 条明细表 | 区域数据钻取段 |
| 明细与导出 | 按四个指标升/降序排列，展示前 100 条，一键下载当前筛选结果 CSV | 明细数据区 |

## 八、实验小结

1. `st.session_state` 是这个看板的关键：Streamlit 每次交互都会把脚本从头执行一遍，若不用会话状态保存 DataFrame，数据会被反复重置，手动新增的记录也无法累积。
2. 图表选用 Plotly 而非静态图，是为了保留悬停查看数值、缩放与筛选联动的能力；雷达图前先对每个指标做极差归一化，避免量纲差异导致图形失真。
3. 预警把「平均拥堵指数 7.0」和「事故总数 5」两个业务阈值直接写进页面，让看板从单纯展示升级为可监控的工具。
4. 可改进方向：接入真实交通接口替代模拟数据、用 `st.cache_data` 缓存聚合结果、把阈值与主题做成可配置项、增加用户登录与报表定时导出。
